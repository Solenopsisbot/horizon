# Java mod compatibility checklist

Status: active work for Minecraft 26.3. The implementation is tracked in [issue #6679](https://github.com/horizon-rust/horizon/issues/6679). This page is the short progress view; [java-mod-compat.md](java-mod-compat.md) remains the design and phase plan.

Last checked: 3 November 2026, commit `36018dd52`.

## Supported now

- [x] Read Fabric `fabric.mod.json`, NeoForge `neoforge.mods.toml`, and legacy Forge `mods.toml` for bounded identity, dependencies, client-only markers, and entrypoint discovery.
- [x] Discover and run multiple Fabric entrypoints in deterministic order, including object/array containers and the `main`, `client`, `server`, and `preLaunch` kinds. The JVM fallback rejects unknown entrypoint adapters before starting a JVM.
- [x] Discover NeoForge and legacy Forge `@Mod` classes through the native probe path, including multiple classes in one jar.
- [x] Run unsupported entrypoints through the embedded JVM runner as a fallback; `--list-entrypoints` reports discovery without starting a JVM, and NeoForge toml/jarJar/mixin markers are surfaced as diagnostics.
- [x] Expose bounded Fabric loader values: loaded-mod checks, metadata (including authors/contributors/license collections and icon-path optionals), versions, environment type, development marker, root paths, seeded containers, and identity `MappingResolver` queries.
- [x] Expose bounded NeoForge and legacy Forge loader values: mod lists, containers, event-bus access, mod ids, and role-aware client/server selection.
- [x] Register and inspect bounded NeoForge and Forge deferred registrations, holders, registry objects, keys, ids, entry collections, generated `Registry.getHolder`/`getOrThrow` lookups, explicit typed-registration handoff, typed recipe and ingredient data-file declarations, `Item.Properties` stack/durability/crafting-remainder/fire-resistance values, bounded `BlockBehaviour.Properties` strength/resistance/friction/occlusion/tool/random-tick values, `EntityType.Builder` category/dimensions and mob lifecycle values, and `ItemStack.getUseAnimation`/tag-stream façade coverage, and custom payload type identity.
- [x] Infer typed `Item`/`Block` declarations from ordinary Java construction: `Item.Properties` (`stacksTo`, `durability`, `rarity`, crafting remainder, fire resistance) and `BlockBehaviour.Properties` (`strength`, `friction`, speed/jump factors, random ticks, occlusion, tool requirements) chains are recorded on the constructed value marker, and a plain `Registry.register` exports `max_stack_size`, `rarity`, `crafting_remainder`, `hardness`, `explosion_resistance`, `friction`, and `requires_tool`. Explicit `META-INF/horizon-native.json` declarations still override inference. Inferred items/blocks name the real vanilla `minecraft:stick`/`minecraft:stone` templates so the content planner can resolve them.
- [x] Record Fabric events, NeoForge events, and legacy Forge event-bus listeners with ordering, cancellation markers, unregister support, and Forge `register(Object)` handlers.
- [x] Record custom payload registrations for the supported Fabric/NeoForge directions, retain custom payload type identity, and support the bounded legacy Forge `SimpleChannel.registerMessage` alias, with bounded `FriendlyByteBuf` value round trips.
- [x] Implement a real bounded `FriendlyByteBuf`: a 1 MiB big-endian buffer with a read cursor round-trips primitives, varints, UTF-8 strings, identifiers, UUIDs, block/chunk positions, byte arrays, nullable/optional values, and enum ordinals, plus cursor operations. NBT remains an opaque bounded marker.
- [x] Provide bounded NeoForge and legacy Forge capability/`LazyOptional` markers, NBT values, identifiers, resource keys (including `ResourceKey.location`), capability `orEmpty`/`orElse` values, bounded declared-field reflection, arrays, reflection metadata, collections (including `removeIf` and `Iterator.forEachRemaining`), maps (including `entrySet`/`Map.Entry` equality and hashing, `computeIfPresent`, and `merge`), primitive optionals (`OptionalInt`, `OptionalLong`, `OptionalDouble`), streams (including runtime-owned `toArray` results and `Collectors.toList/toSet`), and optionals.
- [x] Provide common Java wrapper/string/collection operations used by loader bootstrap code, including integer/long/float/double/byte/short/character conversion, `Number` accessors, checked math, seeded `System.currentTimeMillis`/`identityHashCode`, seeded `System.getProperty(key, default)` and `System.getenv` queries, deterministic `Thread.currentThread`/`getName`/`isDaemon`/`getContextClassLoader` markers, bounded callback combinators, `Arrays.asList`, `Objects.hashCode`/`requireNonNullElse`, and a restricted `String.format` subset.
- [x] Close the common reflection gaps: primitive `TYPE` classes, reflective argument unboxing, `Field.get/set`, enum constants/`values()`/`valueOf`/name/ordinal through the superclass, bounded annotation proxies, record `equals`/`hashCode`/`toString`, and `Constructor.newInstance`.
- [x] Provide bounded `ClassLoader.getResource`/`getResourceAsStream`/`getResources` markers from explicitly seeded `StdHost::with_resource` entries and every non-class file bundled in a `NativeJar::seed_host` jar with bounded byte-backed `InputStream` reads, `available`, `skip`, `skipNBytes`, mark/reset, and close support, explicitly seeded `ClassLoader.loadClass` markers, current-jar `Class.forName`, bounded field reflection, and explicitly seeded `ServiceLoader` providers and iterators; these queries never scan host files or the process classpath.
- [x] Discover Mixin translation plans from real annotations: `@Mixin` targets and `@Inject` methods with `method` (name or `name(descriptor)`), `@At` anchors `HEAD`/`RETURN`/`TAIL`, and `cancellable` become deterministic `MixinInjectionPlan`s. `NativeJar::execute_discovered_mixins` runs HEAD callbacks in declaration order, the target once, then RETURN/TAIL callbacks on the same target, validating every callback before running any. Cancellable HEAD plans get a runtime-owned `CallbackInfo`; `cancel()` stops the remaining callbacks and the target and returns the default value. RETURN/TAIL callbacks get a `CallbackInfoReturnable` carrying the real result, and `setReturnValue` overrides it. `@At(value = "INVOKE", target = ...)` plans parse descriptor, slashed/binary `owner.method(...)` and `owner#name` selectors; the interpreter runs their hooks before the matched call (cancellable hooks suppress the call and return the descriptor default) and reports matched sites. Unparseable INVOKE selectors stay report-only. `--mixin-plans` reports plans, unresolved selectors and targets without an entrypoint.
- [x] Preserve every Mixin config/annotation detail in the census: `@At` selector values (`target`, `args`, `ordinal`, `shift`, `by`, `desc`, `id`, `remap`), nested `@Slice` boundaries, `@Group` constraints, Mixin Extras injector families (`wrap-operation`, `wrap-with-condition`, `modify-expression`, `modify-receiver`), config edge values, priority/order metadata, and access-widener/access-transformer discovery including namespaces.
- [x] Expose bounded `EntityType`/`MobCategory`/`SpawnPlacements`/`EntityDimensions` façade values, including builder spawn flags, dimensions, descriptions, despawn distances, and bounded spawn-placement registration state.
- [x] Provide bounded Fabric API bootstrap façades for `ServerLifecycleEvents`, `ClientLifecycleEvents`, `ServerPlayerEvents`, `CommandRegistrationCallback`, `Event`, `FabricLoader`/`ModContainer`/`ModMetadata`/`ObjectShare`, emitted only when the real API class is absent, with ordered handler dispatch. NeoForge `Event` result/cancel and `SubscribeEvent` metadata are also generated.
- [x] Provide bounded client compatibility façades: Fabric `HudRenderCallback`, `ClientTickEvents`, `KeyBindingHelper` and `ItemTooltipCallback` with real ordered dispatch/retention, plus NeoForge `RegisterKeyMappingsEvent` registration state and tick/render event markers. Client signature types are resolved from the game jar instead of hard-coded.
- [x] Provide bounded item-group and renderer registration façades: Fabric `ItemGroupEvents`/`FabricItemGroupEntries` with ordered per-tab `add`/`addAfter`/`addBefore` and search views, `EntityRendererRegistry`/`BlockEntityRendererRegistry`/`ModelLayerRegistry`/`ColorProviderRegistry` retention, and NeoForge tab-contents/entity-renderer events. Every class is emitted only when the real API is absent.
- [x] Provide bounded Fabric networking façades: `ServerPlayNetworking`/`ClientPlayNetworking` retain receivers per payload type, answer `canSend` from the retained map, and record send directions without delivering packets; `PacketSender`, `Context` and the payload handler shapes link. A real Fabric API jar is never shadowed.
- [x] Emit a bounded classfile writer and weaver: `ClassFile::write` reproduces input bytes exactly, and the weaver appends a callback `invokestatic` at method head for straight-line methods (no branches, exception table, stack-map frames or condy), adjusting `max_stack` and `Code` length. Void methods also get RETURN/TAIL callbacks inserted before every return, and `weave_class`/`weave_classes` apply HEAD then RETURN/TAIL plans per class. Methods with branches, switches, `wide` locals, exception handlers, debug tables and `StackMapTable` frames are relocated correctly (verified by loading rewritten classes), including switch repadding and `goto_w` growth; non-void RETURN/TAIL callbacks are woven by boxing into a synthetic `CallbackInfoReturnable` and unboxing the override; condy, cancellable void, INVOKE and conditional-branch overflow still reject with a reason. `--weave <out.jar>` rewrites a jar end to end.
- [x] Transport Java payload frames over LAN: a declared-channel registry travels on `horizon:payload_channels`, frames use `horizon:payload`, the hub and remote client validate direction and supported codecs (raw/UTF-8/empty) with bounded queues, and send/receive APIs exist on both sides. Mod code still cannot originate a frame until the Java hook API lands.
- [x] Persist declared menu clicks in the block entity: a declared menu over a template inventory opens as the matching vanilla chest menu on `Slots::Block`, so server clicks write the block entity and client prediction follows the same path.
- [x] Materialize declared Java block entities on the client: block-state sync and menu opening resolve a declared block to its template entity, so it appears in the client world and its menu attaches to the block; block-entity updates naming the declared id resolve to the template before decoding.
- [x] Persist and tick declared Java block entities: declarations are published keyed by block, saves write the declared id and decode via the template, chunk encoding/worldgen answer the template type, state tickers follow the template or the declared ticker flag, and hopper checks accept declared templates.
- [x] Instantiate declared Java block entities: a declared block entity maps its `valid_blocks` to the vanilla template entity, drives ticker decisions, and reaches placement, `/setblock`, containers and declared menus. Persistence and chunk-flag handling for the declared id still use the template id.
- [x] Show Java mod identity in the launcher: mod rows read Fabric/NeoForge/Forge metadata in place and show loader, id, version, mixin presence and a conservative compatibility hint.
- [x] Open declared Java menus: a bound block opens a bounded chest menu from its menu declaration, with title, rows and a copied vanilla-template inventory, on the guest/server path.
- [x] Add ABI corpus and differential tooling: `tools/native_java_abi.py` ranks census classes/members/body calls by loader family, and `tools/native_java_differential.py` compares native-probe and JVM-runner outcomes for a compiled fixture.
- [x] Add an exact numeric value model: `Value::Long` and `Value::Float` cover long/float/double constants, arithmetic, bitwise/shifts, comparisons with NaN polarity, conversions with JVM saturation, returns, locals, arrays, boxing and `Long`/`Float`/`Double`/`String` APIs with two-slot arguments and exact constant-pool reads.
- [x] Parse and apply Forge access transformers as well as Fabric access wideners: `META-INF/accesstransformer.cfg` entries (all six access forms, dotted owners, member descriptors, constructors) apply to parsed classes with descriptor-specific matching and missing-target errors.
- [x] Carry nested Fabric JiJ and NeoForge JarJar content into the port output under the nested mod namespace, with bounded files/bytes, deterministic conflicts and skip reasons.
- [x] Parse and apply Fabric access wideners: `accessWidener v1` class/method/field entries with accessible/extendable semantics are validated and applied to parsed classes, preserving constructors and reporting missing targets.
- [x] Parse Fabric and NeoForge dependency metadata: per-mod depends/recommends/suggests/conflicts/breaks maps, sides, orderings, version ranges and nested jar entries, with bounded ids and line-context errors.
- [x] Merge declared content ids into command registries: typed ids for blocks/items/effects/entities/menus/block-entity types are stored with the content root and merged into `by_registry`/`summonable`, so `/summon`, `/give`, `/setblock` and `/fill` resolve mod namespaces.
- [x] Rank method-body call sites in the ABI census: per-jar and aggregate body-call/field-ref counts and bounded errors, with top-N helpers and summary output.
- [x] Inject NeoForge constructor arguments: supported `IEventBus`/`ModContainer`/`FMLModContainer`/`Dist`/`ModList`/`String` parameters are selected widest-first with no-arg fallback.
- [x] Report Mixin planning per jar: the game-facing compatibility report carries resolved plan/target counts, unresolved INVOKE selectors, readable configs and config errors, prints a deterministic `mixin:` summary line, and warns once when anything stays on the JVM fallback.
- [x] Judge Mixin lifecycle phases in the JVM runner: after bootstrap and config registration it attempts `onLoadingDone`, resolves the default environment and sets the client/server side for the selected entry kind, reporting each step.
- [x] Record nested jar metadata: Fabric JiJ and NeoForge JarJar entries are discovered with bounded identity and errors folded into the per-jar info.
- [x] Summarise Java content declarations: a bounded `DeclarationSummary` merges typed tables and native data keys across mods with deterministic lines for logs/UI.
- [x] Provide bounded screen and datagen façades: Fabric `ScreenEvents`/`Screens`, NeoForge `ScreenEvent` markers, and Fabric `DataGeneratorEntrypoint`/`FabricDataGenerator`/output/provider retention. The JVM runner also accepts `--entry-kind datagen` and `--datagen-output`, invokes `onInitializeDataGenerator` and reports retained providers; generation itself is not implemented.
- [x] Provide bounded model-loading façades: Fabric `ModelLoadingRegistry`/`ModelProviderContext` and NeoForge `ModelEvent` registration retain providers, requested ids and model keys in deterministic order, emitted only when the real API is absent.
- [x] Inherit loot from the entity template: declared aliases fall back to their vanilla template table, explicit mod tables win, and non-alias behavior is unchanged.
- [x] Apply declared entity categories and spawn rules: aliases canonicalise a mob category, retain bounded spawn restrictions, feed placement/heightmap tables, and expose the template for loot. The height window itself is still decided in the vanilla spawn selector.
- [x] Make declared mod entities summonable: resource loading scans `data/*/horizon/entity/*.json`, `MobTypes` clones the declared vanilla template with bounded overrides, and `/summon <ns>:<id>` resolves through the alias table. Entities are now consumed by gameplay; menus and block entities are not.
- [x] Hand supplied jars to Fabric Loader through a bounded `-Dfabric.addMods` property (plus opt-in `--fabric-development`), with a read-back diagnostic. The loader's own discovery still does not run.
- [x] Bind menus to blocks in the server snapshot: `menus_for_block`, bounded `menu_bindings`, diagnostics, and atomic rejection of undeclared block targets.
- [x] Bind menus to blocks: menu declarations carry bounded `open_blocks` ids cross-checked against declared/vanilla blocks and block-entity valid blocks, with a `menus_for_block` accessor.
- [x] Provide bounded menu/screen-handler façades: Fabric extended menu types/providers retain the wrapped type, codec and opening data with game-jar role resolution; NeoForge container factories and `IMenuTypeExtension` retain factories/natural ids on the generated `MenuType` stub.
- [x] Fold nested jar metadata into the census: per-jar and aggregate rows carry sorted Fabric JiJ/NeoForge JarJar identities, per-kind counts and bounded metadata errors, with a deterministic summary line.
- [x] Log the merged Java content declaration summary at startup and append bounded declared counts to the aggregate compatibility line.
- [x] Provide bounded attachment façades: Fabric `AttachmentRegistry`/`AttachmentType`/`AttachmentTarget` retain ids, codecs, initializers and flags with a bounded per-target store, and NeoForge `AttachmentType` builders retain the same registration shape.
- [x] Round-trip the native declaration set: `from_native` emits `data/<id>/horizon/{block,item,mob_effect,entity,data_component,attachment,menu,block_entity}/*.json`, and `Content::read` accepts and validates every kind with the same parsers and bounds, so a native content root survives export and re-read.
- [x] Discover and report Mixin configs in the JVM fallback: Fabric/NeoForge metadata and root `*.mixins.json` entries are read from the supplied jars, parsed tolerantly (`package`, `mixins`, `client`, `server`, `required`, `priority`), logged deterministically, and passed to the JVM as a bounded `-Dmixin.configs` property before `org.spongepowered.asm.launch.MixinBootstrap.init` is attempted. After bootstrap, each config is registered through `org.spongepowered.asm.mixin.Mixins.addConfiguration`, with missing/partial failures reported rather than fatal. Configs whose jar entry is absent are named and excluded. Fabric object-form, Quilt and NeoForge mixin entries retain their client/server/`*` environment; the selected entry kind filters both registration and the property, skipped configs are reported once, and `--mixin-config`/`--list-mixin-configs` expose the inventory.
- [x] Read Mixin config metadata in the native probe: `NativeJar::mixin_configs()` discovers Fabric-declared and root `*.mixins.json` entries and parses package/mixin lists/environment lists/required/priority/plugin/refmap with bounded names and sizes, while `mixin_config_errors()` keeps malformed or oversized configs visible. `--mixin-plans` reports both.
- [x] Maintain deterministic Fabric jar fixtures covering entrypoint execution, seeded resources, typed registry declarations, unknown-kind diagnostics, an invokedynamic event listener dispatch, and the Horizon typed content adapter/content-planning path.
- [x] Maintain runtime-built Fabric, legacy Forge, and NeoForge fixtures covering `fabric.mod.json`, `mods.toml`, `@Mod` discovery, `DeferredRegister`, `SimpleChannel.registerMessage`, event-bus listener dispatch, Forge `register(Object)`/`unregister(Object)` handlers, typed inference from item/block builders, a multi-listener Fabric API bootstrap, uncaught exceptions, Mixin annotation discovery and execution, a realistic mod catalog, and the game-facing `--java-mod` content path.
- [x] Preserve bounded Throwable/Exception/Error messages and cause markers, including `getMessage`, `getCause`, `initCause`, and `toString` diagnostics. An uncaught `athrow` now fails native execution with `UncaughtException { class, message }` instead of continuing silently.
- [x] Mirror the common `Locale.US` integer grouping path used by the native statistics screen without emulating arbitrary locale patterns.
- [x] Generate and test the Java façade, including bounded public Mixin `@Accessor`/`@Invoker` stubs, array-returning signatures, common `Identifier` prefix/language-key/ordering helpers, Holder serialization queries, TagKey values, `HitResult`/`BlockHitResult` state and copy factories, bounded `FluidState` queries, bounded `EntityType.Builder`/`MobCategory`/`EntityDimensions`/`SpawnPlacements` values, bounded `Item.Properties` and `BlockBehaviour.Properties` values, `InteractionHand` name/opposite semantics, and the sealed 26.3 `InteractionResult` value records and constants.
- [x] Report Java compatibility decisions per jar: `run_java_mods_with_report` names loader, role (`client`/`integrated-server`/`dedicated-server`), declared and executed entrypoints, typed/promoted/opaque registrations, payload directions, listener counts, and client-only rejection. The dedicated server logs these and exposes a bounded `java` section in server status.

## Partial or report-only

- [ ] Full Mixin weaving. The weaver handles branches, switches, `wide`, exception handlers, debug tables, stack-map frames, HEAD and void/non-void RETURN/TAIL, with `--weave` producing a rewritten jar, but condy, cancellable void, INVOKE and conditional-branch overflow still use the interpreter path. Native execution discovers plans from annotations, runs ordered `@Inject` HEAD/RETURN/TAIL chains, honours HEAD cancellation, and applies bounded `CallbackInfoReturnable.setReturnValue` overrides. `@Redirect`, `@ModifyArg`/`@ModifyVariable`, `FIELD`/`NEW`/`JUMP` anchors, slices, ordinal selectors, `@Overwrite` coexistence, and remapping remain JVM fallback. The census reads config targets, injection annotations, `@At`, plugins, refmaps, and access metadata; it does not execute plugins, apply access changes, or rewrite bytecode. The JVM runner passes discovered configs through the legacy `mixin.configs` property and registers them with `Mixins.addConfiguration`, but Fabric's parsed `LoaderModMetadata` environment filtering and launch-phase semantics are still missing.
- [ ] Unmatched Mixin injection points. They are listed under `hook_points` with an empty `native_hooks` array and counted in `points_report_only`.
- [ ] Java registration markers. Explicit `META-INF/horizon-native.json` declarations, enriched `StdHost::attach_registration_declaration` rows, and inferred item/block declarations now cross the typed sink for blocks/items/effects/recipes/ingredients/entities/data components/attachments/menus/block-entity types plus bounded custom rows; the server thread atomically snapshots sorted blocks/items/entities/data-components/attachments/menus/block-entities with typed templates/declarations and applies mob effects through a bounded helper. Declared entities are now summonable as their vanilla template; menus and block entities are still staged, not opened or ticked.
- [ ] Menu and block-entity content consumption. Declared menus open on the guest/server path, clicks persist into template-backed block entities, declared block entities instantiate/save/tick/materialize on the client, but a declared menu over a block with no inventory is still look-only and some block-name checks outside the ticker/menu paths remain template-blind.
- [ ] JVM fallback coverage. Unsupported native calls, dynamic classpath failures, and reflective or incompatible missing façade members now have explicit diagnostics; the JVM path still needs broader loader façades and real-mod fixtures.
- [ ] Java classpath discovery. The census reports `ServiceLoader`, arbitrary `ClassLoader` loading, and `Class.forName` as dynamic diagnostics. Native `ServiceLoader.load`/`loadInstalled`, `ClassLoader.loadClass`, and current-jar `Class.forName` now support only explicitly bounded values; arbitrary external discovery and resources outside the loaded jar remain report-only.
- [ ] Numeric fidelity. Primitive arithmetic is exact now; `Math.*` float/double helpers, formatted `%f` precision, hex float parsing and a few `Long` utilities remain unmodelled.

## Remaining work

- [ ] Emit a native hook or rewritten classfile for each supported Mixin plan, and add a JVM fallback for unsupported transforms (the translation pipeline currently stops at native invocation).
- [ ] Add broader real-mod integration fixtures for registries, networking, capabilities, entities, menus, resource loading, and client/server separation; current fixtures cover client/server role rejection, typed inference, a Fabric API bootstrap, and typed content merging.
- [ ] Connect translated callbacks to the generated typed native API and complete live registry synchronization across Horizon's server-thread and dedicated-server boundaries; integrated-server startup now runs bounded Java entrypoints with role diagnostics and rejects conflicting registry batches.
- [ ] Consume the staged `horizon/entity`, `horizon/menu`, and `horizon/block_entity` declarations in gameplay, and complete live content registration and registry synchronization for code-declared blocks, items, entities, data maps, attachments, menus, and custom ingredients.
- [ ] Expand client compatibility for HUDs, key mappings, tooltips, models, renderers, particles, screens, and shader-facing code.
- [ ] Add dedicated-server performance measurements, crash isolation, permissions, and a clear unsupported-call report in the launcher; bounded dedicated Java loading, role-specific failures, and a status section now exist.
- [x] Define the distribution policy for Java jars, native translations, signatures, and per-mod compatibility levels: [java-mod-distribution.md](java-mod-distribution.md) covers artifacts, tiers, trust, licensing, cache keys, telemetry and a support checklist.

## Validation snapshot

- `horizon-native-java`: 165 unit tests passing (plus 7 probe CLI tests), including annotation parsing, Mixin plan discovery/execution, INVOKE hooks, HEAD cancellation and RETURN/TAIL return-value overrides, Mixin config metadata, typed inference from item/block builders, uncaught-exception diagnostics, registry statics/register rows, bounded jar-resource stream reads and cursor operations, Fabric `MappingResolver` identity queries, and bounded Map.Entry equality/hashing; plus 27 runtime-built fixture suites (119 passing tests, no ignored gaps) covering Fabric, NeoForge, legacy Forge, Fabric API events, capabilities and item handlers, Mixin discovery/execution/cancellation/returns/INVOKE/configs/mixed anchors, classfile round-trip/HEAD/RETURN/frame-aware weaving, long/float/double arithmetic, typed inference, uncaught exceptions, and the realistic mod catalog.
- `horizon-mods`: 67 unit tests passing, plus the runtime-built typed declaration adapter fixture. Typed entities carry spawn/attributes, menus/block-entity types emit bounded planner files, and the content reader round-trips every declaration kind (blocks, items, effects and the auxiliary tables).
- `horizon-port-pack`: 252 unit tests passing, including bounded `Item.Properties`/`BlockBehaviour.Properties` façade values, entity/spawn-placement façades, Fabric API event, client HUD/key/tooltip and item-group/renderer dispatch, NeoForge event result/cancel, a real bounded `FriendlyByteBuf`, Mixin `@At`/slice boundary metadata and values (including descriptors and nested `@At` slices), Mixin Extras injector normalization, screen/datagen/model façades, access-widener/access-transformer application, nested-jar metadata and carrying, model-loading façades, loader ABI classification, Mojang codec/datafixer ABI coverage, native declaration-kind reporting, deduplicated Mixin hook matching, Class.forName boundary diagnostics, Registry holder lookup bodies, Identifier façade bodies, sealed InteractionResult façade values, BlockHitResult state coverage, and descriptor normalization coverage.
- `horizon-jvm`: 56 unit tests passing, including entrypoint container/adapter parsing, `preLaunch` selection, `--list-entrypoints` formatting, Mixin config discovery/reporting/registration/environment filtering, the bounded `mixin.configs` and `fabric.addMods` properties, fallback labels, static-initialization fallback diagnostics, and bounded NeoForge constructor argument injection with no-arg fallback.
- `horizon-client`: 407 game/bin and 950 lib tests passing, including bundled-resource loading, typed content, client/server role selection, client-only NeoForge rejection, compatibility reports with Mixin planning, and registry snapshots with menus/block-entity types, declared mod entities resolving through `/summon`, and declared ids merged into command registries.
- Workspace check, full client clippy, compatibility-crate clippy, formatting, and `tools/native_java_smoke.py` passing with registry, payload, Mixin-plan, and plain-CLI assertions.

Every compatibility commit should update this checklist when a surface moves between these sections and should include the focused test or probe that justifies the change.
